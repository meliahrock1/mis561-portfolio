**Certification - Introduction to Power BI:** MIS 561, 9/26/2026 (https://public.tableau.com/views/PowerBITrainingCertifications_17903843295320/PowerBIStory?:language=en-US&publish=yes&:sid=&:redirect=auth&:display_count=n&:origin=viz_share_link)

In the course's previous Excel work, I had to manually clean and transform data before I could begin my analysis and visualizations. For example, in a previous assignment, we had to use Text to Columns in Excel to separate fields and then use Tableau to visualize the data. In Power BI, I can complete those transformations directly in Power Query, while the Applied Steps automatically keep a record of each change made to the data. For a dataset that needs to be updated or analyzed repeatedly, I would choose Power BI because those transformations become part of a repeatable process instead of something I would need to recreate manually in Excel. I would still use Excel for smaller or one-time analysis, but Power BI makes more sense when I expect the underlying data to change over time. 

**Certification - Introduction to DAX in Power BI:** MIS 561, 9/28/2026 (https://public.tableau.com/views/PowerBITrainingCertifications_17903843295320/PowerBIStory?:language=en-US&publish=yes&:sid=&:redirect=auth&:display_count=n&:origin=viz_share_link)

In my first analysis, I used an Excel pivot table to manually summarize the average three-year growth rate for each industry after joining and formatting the underlying data. In Power BI, I would create the average three-year growth rate as a measure because it can automatically recalculate based on the industry or other filters selected in the report. This would be especially useful as the dataset changes because I would not have to rebuild the pivot table or create separate summaries for different views of the data. Instead, the business user could interact with the report and answer different questions using the same measure without needing me to create a new analysis each time.
